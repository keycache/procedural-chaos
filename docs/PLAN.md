# Procedural Chaos — Plan

Phased plan for a toy, client-side app with two independent studios: **Part 1 — Mandala Studio** and **Part 2 — Video Studio**. Technical details are in [SPECIFICATIONS.md](./SPECIFICATIONS.md).

Build order: foundation → Part 1 editor and outputs → Part 1 ornamental-generation phases 3.1–3.5 → Part 2 → later enhancements. Each phase should leave the app in a usable state.

---

## Phase 0 — Foundation

**Goal:** A runnable app shell with shared building blocks, deployed at `https://{username}.github.io/procedural-chaos/`.

- Scaffold Vite + React + TypeScript (strict), Tailwind, shadcn/ui, ESLint/Prettier, and Vitest.
- Configure Vite's `base: '/procedural-chaos/'`, add `public/.nojekyll`, and use hash routing so direct links and refreshes work on GitHub Pages.
- Deploy a styled **Hello Procedural Chaos** test screen before building the engines.
- App shell with hash routes for `/mandala`, `/video`, and `/library`; dark theme; shared studio layout (top bar, settings panel, preview, optional bottom bar).
- Shared utilities: seeded PRNG, vector/geometry helpers, color helpers (`culori`), Zod schema helpers.
- IndexedDB setup with `idb` and empty stores.
- Worker setup with Comlink and a sample worker.
- Browser feature detection with a friendly message for unsupported browsers.

## Phase 1 — Part 1: Geometry and symmetry core

**Goal:** Generate simple, deterministic, symmetric line art.

- Geometry model and SVG renderer.
- Symmetry expansion: rotational, dihedral, bilateral, and none.
- Base geometries: circle, polygon, star, spiral, and freeform boundaries.
- First motifs: petal, arc, dot, polygon, star, and teardrop.
- Ring distribution and layer separator boundaries.
- Recipe schema plus Zod validation.

**Done when:** the same recipe and seed always produce identical SVG output, and a basic radial mandala renders in the studio.

**Implemented locally:** the framework-free engine validates recipes, builds six starter ring motifs, expands symmetry, and renders SVG line art. The Mandala Studio exposes seed, base geometry, symmetry mode, and division controls, with zoom/pan and explicit validation errors. Automated checks cover deterministic output, layer seed isolation, all five geometries with all four symmetry modes, motif closure, validation, and SVG serialization. No commits or deployment are performed by the assistant.

## Phase 2 — Part 1: All styles and hybrid blending

**Goal:** Generate traditional, geometric, organic, and abstract mandalas.

- Style resolver and blend weights (for example, 70% traditional and 30% geometric).
- Distributions: grid, spiral, branching, tessellation, and scatter.
- More motifs: leaf, spiral, branch, and interlocking polygons.
- Transformations: recursion, scaling, twist, distortion, and controlled noise.
- Abstract options: multiple centers and broken symmetry.
- Closure pass so generated designs have closed, fillable regions.

**Done when:** each style and several hybrids produce visually distinct, reproducible line art suitable for coloring.

**Implemented locally:** the studio now generates all four styles and normalized weighted hybrids. Seeded band planning alternates broader ornament bands with narrow beaded/interlocking borders; nested contours, veins, and varied stroke weights add detail. All six distributions and ten motifs are available in the engine, alongside bounded recursion/scaling, twist, distortion, noise, multiple focal centers, and deliberately broken symmetry. Styled subpaths are closed, with endpoint snapping and finite-coordinate validation. Arbitrary intersection simplification and region detection are not part of this closure pass.

Minimal style, blend, complexity, placement, and growth controls are included now so the engine is testable; the full editor, workers/debouncing, saving, and exports remain in Phase 3. Generation has a 24,000-path safety limit and reports errors rather than silently truncating artwork. No commits or deployments are performed by the assistant.

**UI checks:**

1. Open `#/mandala`, then switch among the four styles. Expect distinct motifs/distributions; abstract starts with three focal centers.
2. Select hybrid and vary the weights, including traditional/geometric and organic/abstract mixes. Expect reproducible combined rules and a normalized contribution summary. All-zero weights must show an error; restoring defaults or adding a positive weight recovers.
3. Compare low/high complexity and different seeds. Expect changes in band hierarchy and detail; restoring the same seed/settings restores the exact drawing.
4. Override base geometry, symmetry/divisions, all six distributions, and focal centers. Main bands change placement, while ornamental borders remain rings. Style-guided options and the restore button clear overrides.
5. Expand growth controls; compare recursion depth 0/3, twist, noise, distortion, and broken symmetry. Transformations change geometry; broken symmetry/multiple centers are explicitly labeled.
6. Verify zoom/pan/reset still work, empty seeds show errors instead of stale artwork, and Video Studio remains independent. Save/export remain disabled until Phase 3.

## Phase 3 — Part 1: Studio UI and outputs

**Goal:** A polished Mandala Studio.

- Presets for each style and hybrid.
- Seed controls, randomize, and seed history.
- Global controls and per-layer editor (add, remove, duplicate, reorder, enable/disable).
- Generation in a worker with debounced updates; Canvas preview for dense designs if needed.
- Undo/redo.
- Export SVG with metadata, PNG at a chosen resolution, and JSON recipe.
- Save mandalas to the Library and reopen them.

**Done when:** a user can create, tune, save, reload, and export mandalas without UI freezes.

**Implemented locally:** the studio includes six curated presets (four styles/two hybrids), seed randomization and 12-entry recent history, global density/negative-space/irregularity/stroke controls, and editable layers with add/duplicate/remove/reorder/enable operations. A 100-edit undo/redo history restores exact documents. Style/structure changes rebuild custom layers with explicit UI guidance; appearance changes retain them. Added/removed bands redistribute radial widths; moving swaps radial slots.

Generation and SVG serialization run in cancellable module workers after a 200 ms debounce; obsolete results are rejected, errors are visible, and stalled workers time out after 15 seconds. The SVG image preview remains responsive without a separate Canvas preview renderer. The existing desktop sticky preview is retained.

SVG exports include recipe/center/symmetry metadata and path draw order; PNG supports 1024/2048/4096/8192 pixels and white/transparent backgrounds; JSON exports the exact engine recipe. Named projects save to IndexedDB with previews and complete editor state. Library reopen survives refresh; Save updates an existing project and Save a copy creates a new one. Undo/recent-seed history are session-only. JSON import and library delete/management are not implemented in this slice. No commits or deployments are performed by the assistant.

**UI checks:**

1. Select all six composition presets, randomize seeds, and reuse recent seeds. Expect distinct artwork and exact repetition with the same settings.
2. Expand global appearance and compare density, negative space, irregularity, and stroke width. Adjust sliders quickly: controls should remain usable and only the latest recipe should appear after generation.
3. Edit a layer's motif, distribution, repetitions, scale, radial bounds, and detail. Add/duplicate/move/disable/remove layers, then undo/redo. Expect custom geometry to change and exact prior drawings to return. Invalid radial/count settings show errors and remain editable.
4. Scroll down to layer and export controls on desktop; expect the preview to remain visible. Narrow layouts remain stacked.
5. Name and save a custom design, visit Library, refresh, and reopen. Expect identical artwork and editor settings; Save updates one card, while Save a copy adds another.
6. Export SVG/JSON and compare their recipes. Export white and transparent PNGs at different selected sizes; expect matching square dimensions, correct backgrounds, and unchanged geometry. Exports/save are disabled during pending or failed generation.
7. Verify Video Studio remains an independent placeholder and the foundation worker/storage tests still work.

## Phase 3.1 — Part 1: Bold floral composition

**Goal:** Prove a visibly stronger design language with one convincing bold-floral composition before adding more controls or detail.

**Status:** Implemented locally. Phases 3.4–3.5 remain planned. All generation remains deterministic and entirely client-side. The references guide visual qualities, not exact reproductions.

- Build an art-directed floral composition with a central rosette, dominant leaves, alternating secondary petals, curling tendrils, and a scalloped outer silhouette.
- Introduce compound Bézier motifs and tapered, selectively solid-black accents. Use expressive proportions and intentional empty space rather than increasing path count everywhere.
- Allow prominent petals to span radial bands; do not force every composition into concentric separator rings.
- Establish explicit front-to-back ordering and prototype overlap masking so rear outlines do not show through foreground petals. Keep visible SVG and PNG output consistent.
- Distinguish colorable outlines, decorative strokes, and solid accents in the geometry/export metadata. Closed paths alone are not proof of clean coloring regions; Part 2 still performs region detection.
- Start with one curated composition and a small set of bounded seeded variations. Reuse the current symmetry, worker, preview, and export infrastructure.
- Preserve existing recipes and rendering behavior; add the new composition as an explicit opt-in rather than silently replacing current styles.

**Done when:** the floral preset has a strong silhouette, readable large forms, deliberate black/white contrast, and balanced spacing at both thumbnail and full-preview sizes. Establish this visual baseline before generalizing the ornament engine.

**Implemented locally:** the opt-in **bold-floral** style and **Floral flourish** preset use compound cubic-Bezier crowns, nested hatched leaves, mirrored curls, two central petal crowns, and tapered solid-black accents. Seeded variations change fullness, crown/leaf heights, and curl turns within the same art-directed composition. Six/eight/ten/twelve rotational divisions adapt motif widths; complexity adds bounded decoration without changing the primary silhouette, and stroke width preserves the contour/detail hierarchy.

SVG foreground-silhouette masks remove rear lines behind closed foreground forms without white backing paint, preserving transparent exports. Paths carry explicit outline/decoration/solid-accent roles and occluder flags. A versioned optional composition recipe bypasses ring planning; existing recipes retain their original rendering. Inapplicable ring/layer/blend controls are hidden for floral mode. Workers, undo/redo, preset matching, Library save/reopen, and SVG/PNG/JSON exports are reused. The shared ornament vocabulary and ornate lotus are detailed below; swirling paisley remains planned. No commits or deployments are performed by the assistant.

**UI checks:**

1. Select the new floral preset and compare it with the existing traditional preset. Expect large expressive forms, tendrils, black accents, and an outer petal silhouette—not merely denser rings.
2. Try several seeds, then restore the original seed/settings. Expect coherent variations and exact reproduction.
3. Zoom in and export SVG/PNG. Check smooth curves, clean overlaps, preserved accents, and matching visible geometry.
4. Compare 6/8/10/12 floral divisions and low/high complexity. Expect adapted crown/leaf widths and controlled extra detail, not more separator rings. Changing settings shows Custom composition; Undo restores the selected preset and exact artwork.
5. Save/reopen a floral project, then reopen an existing band-based project. Expect exact drawings/settings in both cases. Switch families and undo to recover custom layers.

## Phase 3.2 — Part 1: Shape-aware ornament vocabulary

**Goal:** Generalize the successful floral design into reusable motifs that contain well-composed interior decoration.

**Status:** Implemented locally. Existing recipes and Classic floral retain their previous rendering; new treatments are opt-in.

- Extract reusable parameterized lotus petals, leaves, paisleys, tendrils, scallops, and beaded borders from the validated design approach.
- Define motif-local contours, interior usable areas, attachment points, and curved spines so decorations follow their parent shape.
- Add contour-following inset borders, veins, curls, dots, and nested smaller petals. Use shape-appropriate patterns rather than stamping every decoration into every motif.
- Enforce minimum spacing, border clearance, and feature-size limits. Bound subdivision/detail work and surface unsupported settings or complexity limits explicitly.
- Separate primary outlines, secondary forms, fine decoration, and solid accents with a restrained stroke-weight hierarchy.
- Keep intentional decorative open strokes distinct from closed colorable boundaries; do not force-close every decorative curve.
- Add focused deterministic geometry tests and a small fixed-seed visual comparison set. Do not equate path count with visual quality.

**Done when:** the motif vocabulary produces clean, recognizably different ornaments with detail that follows each shape, without accidental protrusions or unreadable micro-patterns.

**Implemented locally:** reusable parameterized leaves, lotus petals, paisleys, scallops, curls, and arc-length-spaced bead borders. Closed motifs expose sampled contours, usable longitudinal ranges, paired-side coordinate mappings, attachment points, and curved spines. Three fixed-seed comparison presets add contour lace, botanical filigree, and paisley jewels to the existing floral family. Complexity controls bounded detail; Ornament spacing controls clearance and repeated-detail gaps.

Candidate fitting measures stroke-aware border clearance and minimum feature size, with conservative curve-sampling bounds. Beads also enforce pairwise edge gaps around tips and the closed seam. Unsafe candidates are rejected whole and reported in preview/SVG metadata; empty readable output and exceeded work budgets are explicit errors. Primary silhouettes, foreground masking, stroke roles, and transparent output remain intact. Intentional vein/leaf attachments are not arbitrary collision-free packing. Undo/preset matching, old-document reopening, project persistence, and exports include optional versioned ornament settings. A compatibility fingerprint protects the exact original floral SVG.

**UI checks:**

1. Compare available ornament treatments on the floral composition. Expect details to remain inside the intended outlines with visible clearance.
2. Vary ornament detail and spacing. Expect controlled changes, preserved large forms, and explicit limits rather than freezes or silently truncated drawings.
3. Inspect low/high detail at normal preview size and in an exported image. Fine lines must remain subordinate to the primary silhouette.
4. Compare Contour lace, Botanical filigree, and Paisley jewels presets at their shared seed/settings. Choose Classic floral to recover the original rendering; Undo should restore the selected treatment and exact drawing.
5. Save/reopen a new-treatment project and export SVG, JSON, and transparent/white PNGs. Expect the same settings, artwork, and foreground masks after reopening or exporting.

## Phase 3.3 — Part 1: Ornate layered lotus

**Goal:** Generate intricate botanical mandalas with overlapping petal crowns and nested ornament, inspired by the second reference.

**Status:** Implemented locally as the opt-in **ornate-lotus** mode and **Ornate layered lotus** preset. Existing families and recipes remain unchanged.

- Add a hierarchical composition planner: central rosette → dominant petal crowns → offset secondary crowns → outer scallops and border details.
- Coordinate crown counts, angular offsets, petal lengths, and widths so layers interleave deliberately instead of colliding randomly.
- Decorate each petal with the shape-aware vocabulary from Phase 3.2, keeping interior ornament subordinate to its parent shape.
- Generalize overlap ordering/masking for nested crowns; keep covered rear contours and ornaments out of the visible rendering.
- Balance quiet areas with dense areas and vary detail by structural role. Increasing complexity should enrich a composition, not erase its hierarchy.
- Offer a curated ornate-lotus preset with bounded seeded variation before exposing additional advanced controls.

**Done when:** the design reads as a layered flower at thumbnail size and reveals coherent nested botanical detail when enlarged, without a mesh of uncontrolled intersections.

**Implemented locally:** six coordinated crowns progress from outer scallops through dominant lotus petals and a double-count offset leaf crown to curled inner petals and two rosette crowns. Shape-aware templates provide subordinate insets, beaded borders, botanical veins/leaf sprays, and paisley curls. Per-crown spacing/detail budgets balance quiet areas with dense ones; complexity preserves the primary silhouettes. Seeded fullness, heights, bend, and scrolls vary within the curated composition.

All petal control points stay inside disjoint convex angular envelopes, preventing sibling intersections without breaking rotational symmetry. A shared petal-composition builder emits contiguous back-to-front crown groups for the existing transparent SVG silhouette masks: later crowns hide both rear outlines and ornaments. Six/eight/ten/twelve divisions coordinate crown widths/counts/offsets. Stroke widths are limited to 0.25–4 to keep central ornaments readable. Runtime generation is capped at 4,000 paths with explicit fitting errors and omitted-detail reporting.

An additive version-1 composition recipe, editor mode/preset, contextual help, history/default resets, Library storage, and SVG/PNG/JSON outputs reuse existing infrastructure. Ring/layer/blend and global ornament-override controls are intentionally absent in lotus mode. No commits or deployments are performed.

**UI checks:**

1. Select the ornate-lotus preset. Expect interleaved petal crowns and a clear center-to-edge hierarchy distinct from the bold-floral family.
2. Compare lower/higher detail and several seeds. Large floral structure should stay readable while interior ornament changes.
3. Inspect overlapping petals at high zoom and in SVG/PNG exports. Rear outlines must not bleed through foreground forms.
4. Compare 6/8/10/12 Petal divisions, restore the preset, and undo a style switch. Expect coordinated crowns, accurate selected-preset state, and exact artwork restoration.
5. Save/reopen through Library after refresh, then export SVG, JSON, and transparent/white PNGs. Expect the same recipe/artwork and no opaque white petal interiors in transparent output.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Generated mandalas contain gaps or messy tiny regions | Closure pass plus Part 2 gap closing and minimum region size |
| More ornament produces clutter rather than stronger artwork | Validate a bold-floral baseline first; enforce hierarchy, spacing, contrast, and a fixed-seed visual-quality gate |
| Overlaps, decorative strokes, or black accents confuse coloring | Preserve drawing roles and visible overlap behavior in exports; distinguish decoration from region boundaries during Part 2 preparation |
| Dense ornament overwhelms browser generation or rendering | Bounded detail/packing, measured complexity budgets, worker cancellation/timeouts, and explicit errors |
| Imported art leaks between regions | Gap-closing slider and manual split tool |
| Symmetry detection is imperfect | Manual center/order/axis override and group editing |
| Preview is slow with many regions | Accumulated fill canvas, cached pixel spans, reduced preview resolution |
| Export memory use grows with long videos | Initial target of about 10 minutes; consider streaming output later |
| Browser API differences | Desktop Chrome/Edge first; feature detection elsewhere |
