# Procedural Chaos — Plan

Phased plan for a toy, client-side app with two independent studios: **Part 1 — Mandala Studio** and **Part 2 — Video Studio**. Technical details are in [SPECIFICATIONS.md](./SPECIFICATIONS.md).

Build order: foundation → Part 1 → Part 2 → later enhancements. Each phase should leave the app in a usable state.

---

## Phase 0 — Foundation

**Goal:** A runnable app shell with shared building blocks, deployed at `https://{username}.github.io/procedural-chaos/`.

- Scaffold Vite + React + TypeScript (strict), Tailwind, shadcn/ui, ESLint/Prettier, and Vitest.
- Configure Vite's `base: '/procedural-chaos/'`, add `public/.nojekyll`, and use hash routing so direct links and refreshes work on GitHub Pages.
- Deploy a styled **Hello Procedural Chaos** test screen before building the engines.
- App shell with hash routes for `/mandala`, `/video`, and `/library`; dark theme; shared studio layout (top bar, settings panel, preview, optional bottom bar).
- Shared utilities: seeded PRNG, vector/geometry helpers, color helpers (`culori`), Zod schema helpers.
- IndexedDB setup with `idb` and empty stores.
- Worker setup with Comlink and a sample worker.
- Browser feature detection with a friendly message for unsupported browsers.

### 0.1 Scaffold and configure

Use a Vite-supported Node LTS version (Node 24 for this project). Add `.nvmrc` containing `24` so local development and CI use the same major version.

Run from the repository root:

```bash
npm create vite@latest . -- --template react-ts
npm install
npm install react-router-dom zustand zod culori idb comlink sonner lucide-react class-variance-authority clsx tailwind-merge @fontsource-variable/geist tw-animate-css
npm install -D tailwindcss @tailwindcss/vite @types/node gh-pages typescript@~6.0.0 vitest fake-indexeddb eslint@^10 @eslint/js@^10 typescript-eslint globals eslint-plugin-react-hooks eslint-plugin-react-refresh prettier
```

The repository already contains documentation and other files. If the scaffolder prompts about the non-empty directory, choose **Ignore files and continue**, not removal. Preserve existing files and merge any generated `.gitignore` entries with the existing ones.

The latest Vite template may use a different linter or newer TypeScript version. Use ESLint as specified here; the foundation currently uses TypeScript 6 because it is supported by `typescript-eslint`.

Before initializing shadcn/ui:

1. Update `vite.config.ts` with the base path, React/Tailwind plugins, and `@` alias shown in [the hosting specification](./SPECIFICATIONS.md#31-github-pages-and-vite-configuration).
2. Add the `@/*` TypeScript alias to both `tsconfig.json` and `tsconfig.app.json`, preserving their existing settings.
3. Start `src/index.css` with `@import "tailwindcss";`.

Then initialize shadcn/ui and add the test screen's components:

```bash
npx shadcn@latest init --base radix --preset nova --yes --no-monorepo
npx shadcn@latest add button card badge
```

Use the **Radix** component base, a neutral theme, and CSS variables for the examples in the specification. Keep the theme CSS generated by the CLI. Commit `package-lock.json` so deployment can use `npm ci`.


Check the local app under `/procedural-chaos/`. After stopping the development server, verify the production build:

```bash
test -f dist/.nojekyll
```

Open `http://localhost:4173/procedural-chaos/` (or the printed preview address). Confirm the styling, counter, and hash-route navigation work; refresh a studio route to check direct-link behavior.

### 0.3 Deploy the test app

1. Add `predeploy` and `deploy` npm scripts using [the deployment specification](./SPECIFICATIONS.md#33-github-pages-deployment).
2. Run `npm run deploy`. Its `predeploy` hook runs lint, tests, and the production build, then the `gh-pages` package commits and pushes `dist/` to the remote `gh-pages` branch. `--dotfiles` includes `.nojekyll`.
3. In the repository's **Settings → Pages → Build and deployment**, select **Deploy from a branch**, then **gh-pages / (root)**.
4. Verify `https://{username}.github.io/procedural-chaos/` shows **Hello Procedural Chaos** and loads its JavaScript and CSS without 404 errors. The configured remote is `keycache/procedural-chaos`, so the current URL is `https://keycache.github.io/procedural-chaos/`.
5. Test the click counter and open/refresh the `#/mandala`, `#/video`, and `#/library` routes.

```bash
npm run deploy
```

Commit the source, configuration, documentation, and lockfile separately on the main branch when ready. `gh-pages` publishes only the build output; it does not commit the source tree. No custom GitHub Actions workflow is required, and the hosted application has no backend.

**Done when:** the test app works at the GitHub Pages URL, both studios load with placeholder previews after direct navigation/refresh, `.nojekyll` is present in the build, and the remaining foundation utilities and tests run.

## Phase 1 — Part 1: Geometry and symmetry core

**Goal:** Generate simple, deterministic, symmetric line art.

- Geometry model and SVG renderer.
- Symmetry expansion: rotational, dihedral, bilateral, and none.
- Base geometries: circle, polygon, star, spiral, and freeform boundaries.
- First motifs: petal, arc, dot, polygon, star, and teardrop.
- Ring distribution and layer separator boundaries.
- Recipe schema plus Zod validation.

**Done when:** the same recipe and seed always produce identical SVG output, and a basic radial mandala renders in the studio.

---

## Phase 2 — Part 1: All styles and hybrid blending

**Goal:** Generate traditional, geometric, organic, and abstract mandalas.

- Style resolver and blend weights (for example, 70% traditional and 30% geometric).
- Distributions: grid, spiral, branching, tessellation, and scatter.
- More motifs: leaf, spiral, branch, and interlocking polygons.
- Transformations: recursion, scaling, twist, distortion, and controlled noise.
- Abstract options: multiple centers and broken symmetry.
- Closure pass so generated designs have closed, fillable regions.

**Done when:** each style and several hybrids produce visually distinct, reproducible line art suitable for coloring.

---

## Phase 3 — Part 1: Studio UI and outputs

**Goal:** A polished Mandala Studio.

- Presets for each style and hybrid.
- Seed controls, randomize, and seed history.
- Global controls and per-layer editor (add, remove, duplicate, reorder, enable/disable).
- Generation in a worker with debounced updates; Canvas preview for dense designs if needed.
- Undo/redo.
- Export SVG with metadata, PNG at a chosen resolution, and JSON recipe.
- Save mandalas to the Library and reopen them.

**Done when:** a user can create, tune, save, reload, and export mandalas without UI freezes.

---

## Phase 4 — Part 2: Import and region detection

**Goal:** Convert any supported illustration into fillable regions.

- Import SVG, PNG, JPG, and WebP; rasterize to the working canvas.
- Read Part 1 SVG metadata when present.
- Region detection worker: threshold, invert, gap closing, labeling, background detection, minimum region size, and adjacency.
- Region overlays and detection tuning controls.
- Manual tools: merge, split, exclude/include, and mark background.
- Cache prepared artwork in IndexedDB.

**Done when:** clean Part 1 mandalas and typical imported coloring pages produce correct regions, and imperfect detections can be fixed manually.

---

## Phase 5 — Part 2: Symmetry detection

**Goal:** Find symmetry groups so related regions can be colored together.

- Center detection with draggable override.
- Radial order detection and mirror-axis detection, with manual override.
- Region grouping by transformed centroid, area, and mask IoU.
- Symmetry-group overlay and manual group correction.

**Done when:** Part 1 mandalas group exactly through metadata, and imported radial or left/right symmetric art groups correctly in most cases.

---

## Phase 6 — Part 2: Sequencing and color

**Goal:** Produce the coloring plan.

- Grouping: individual regions or symmetry groups, with group playback modes.
- Ordering: random, smallest first, largest first, center outward, outside inward, spiral, wave/sweep, farthest jump, and one color at a time.
- Color: palette presets, custom palette editor, symmetry color modes, neighbor-aware assignment, and accent exceptions.
- Deterministic scheduler producing timed fill events.

**Done when:** changing strategies produces visibly different but reproducible coloring plans, and a static “final frame” preview shows the result.

---

## Phase 7 — Part 2: Animation and preview

**Goal:** Watch the coloring process in the browser.

- Frame renderer with accumulated fill canvas.
- Fill animations: instant, fade, spread from a point, and directional wipe.
- Reveal structures: outline first; color first and outline last; animated line drawing for SVG/generated art.
- Timing controls: fill duration, gap, jitter, speed ramp, intro, and outro.
- Transport controls: play/pause, scrub, playback speed, and time display.
- Video Studio presets and saved video projects.

**Done when:** previews play smoothly, scrubbing is accurate, and every configured option is visible in playback.

---

## Phase 8 — Part 2: MP4 export

**Goal:** Export the video.

- Worker-based frame-by-frame rendering with `OffscreenCanvas`.
- WebCodecs H.264 encoding and MP4 muxing with Mediabunny.
- 1080×1080 at 30 fps with a bitrate setting.
- Support check, progress, estimated time remaining, cancel, and download.

**Done when:** exported videos match the preview frame for frame and play in common video players and platforms.

---

## Phase 9 — Later enhancements

Each can be implemented independently.

1. **Thumbnail export:** export a chosen frame as PNG.
2. **Text hooks and CTA overlays:** timed text layers for short-form videos.
3. **Audio:** synchronized fill sound effects first, then optional user music.
4. **Batch variations:** queue multiple seeds or strategies for one artwork.
5. **Side-by-side comparison:** render multiple strategies in one video.
6. **Camera zoom/pan:** keyframes or follow the active region.
7. **Colored static mandalas in Part 1:** reuse the coloring engine.

## Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Generated mandalas contain gaps or messy tiny regions | Closure pass plus Part 2 gap closing and minimum region size |
| Imported art leaks between regions | Gap-closing slider and manual split tool |
| Symmetry detection is imperfect | Manual center/order/axis override and group editing |
| Preview is slow with many regions | Accumulated fill canvas, cached pixel spans, reduced preview resolution |
| Export memory use grows with long videos | Initial target of about 10 minutes; consider streaming output later |
| Browser API differences | Desktop Chrome/Edge first; feature detection elsewhere |
